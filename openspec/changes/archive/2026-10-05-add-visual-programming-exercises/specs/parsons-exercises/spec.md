## ADDED Requirements

### Requirement: Professor authors a Parsons exercise from a working solution
When the lesson owner sets an exercise's answer mode to `parsons`, the system SHALL require a primary language and a solution program. The solution SHALL be run against the problem's test cases when it is saved, and SHALL be saved only if every test case passes. Each non-blank line of the solution, with leading indentation stripped, becomes one draggable item.

#### Scenario: Saving a passing solution
- **WHEN** the lesson owner saves a Parsons solution that passes every test case of the problem
- **THEN** the solution is stored and the exercise's mode is `parsons`

#### Scenario: Saving a failing solution
- **WHEN** the lesson owner saves a Parsons solution that fails at least one test case
- **THEN** the save is rejected and the owner sees which test case failed

#### Scenario: Parsons without a language
- **WHEN** the lesson owner sets the mode to `parsons` without choosing a primary language
- **THEN** the change is rejected with a message asking for a language

### Requirement: Students order shuffled lines to answer
For an exercise in `parsons` mode, the exercise page SHALL show the solution's lines in a shuffled order and let the student drag them into order and set each line's indentation level. Shuffling SHALL happen on the server, and the solution in its original order SHALL never be sent to students.

#### Scenario: Lines are shuffled
- **WHEN** a student opens a `parsons` exercise
- **THEN** the page shows every solution line exactly once, in an order generated by the server, and no student-facing response contains the solution in its original order

#### Scenario: Setting indentation
- **WHEN** a student changes a line's indent level
- **THEN** the line is shown at that level and the level is part of what gets submitted

### Requirement: Parsons answers are assembled on the server and graded by I/O
On submit, the client SHALL send the ordered lines with their indent levels. The server SHALL check that the submission contains exactly the exercise's solution lines (each one as many times as it appears in the solution; identical lines are interchangeable) with indent levels in range, assemble the program in the submitted order and indentation, store the order as the submission's visual source and the assembled program as its `code` in the exercise's primary language, and send it to the judge like any other submission. Correctness SHALL be decided by the judge's I/O grading, not by comparison with the original order.

#### Scenario: Alternative valid order passes
- **WHEN** a student submits an order different from the professor's solution that still produces the expected output on every test case
- **THEN** the submission is graded `PASSED`

#### Scenario: Tampered line list rejected
- **WHEN** a submission for a `parsons` exercise contains a line that is not in the solution, misses one, repeats one more times than the solution does, or has an out-of-range indent
- **THEN** the submission is rejected before reaching the judge

#### Scenario: Wrong indentation fails in Python
- **WHEN** a Python Parsons answer has the right order but a line at the wrong indentation, changing the program's behavior
- **THEN** the judge grades it on the resulting program's output

### Requirement: Parsons submissions are shown as ordered lines
Wherever a student's submission history or the professor's lesson review shows a `parsons` submission, the system SHALL render the submitted lines in order with their indentation.

#### Scenario: Professor reviews a Parsons submission
- **WHEN** the professor opens the lesson review for a student whose exercise answer is a `parsons` submission
- **THEN** the review shows the lines in the order and indentation the student submitted

### Requirement: AI hints for Parsons answers are about order and nesting
When a student requests AI help on a failed `parsons` submission, the hint SHALL be about the order or nesting of the given lines, and SHALL NOT suggest writing new code or changing a line's content.

#### Scenario: Hint on failed Parsons submission
- **WHEN** a student asks for AI help on a failed `parsons` submission
- **THEN** the returned hint points toward which part of the order or nesting to rethink, without rewriting any line
