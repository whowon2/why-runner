## Why

The 2026-10-29 classroom test showed that signup gets in the way of the first lesson. Email signup has no username field, so every new account goes through a separate onboarding page. That page only accepts lowercase usernames, and there was nowhere to enter the IFMG student ID (RA, Registro do Aluno). Students typed their RA into the username field. Teachers then had no reliable way to match accounts to the official class list. Fixing this before the next class session removes a whole step from signup and gives teachers a real RA column.

## What Changes

- **BREAKING** Remove onboarding. Delete the `/onboarding` page, the `completeOnboarding` action and hook, the `requireOnboardedUser` gate and the `user.finished_onboarding` column. All 20+ pages that used the gate switch to a plain `requireUser` helper (it only requires a session).
- Social login (GitHub/Google) keeps the username generated by `generateUsername()` and goes straight to `redirectTo` (default `/home`). The user can change the username later in the profile edit form.
- The email signup form gains a required **username** field, validated on the client and again on the server, plus a case-insensitive uniqueness check. Better Auth's `username` field becomes a signup input. Changing `username`/`ra` through Better Auth's own `/update-user` endpoint is blocked, so edits only go through `updateProfile`.
- Usernames may contain uppercase `A-Z` (`^[A-Za-z0-9.-]+$`, 3–20 chars). The case the user typed is stored. Uniqueness is case-insensitive, enforced by a unique index on `lower(username)` that replaces the current unique constraint. Profile lookups at `/user/[username]` and duplicate checks ignore case.
- New optional `user.ra` column: `text`, nullable, unique, exactly 7 digits with leading zeros kept (e.g. `0064019`). It can be entered on signup and edited in the profile edit form. It is not a public user column. Only the user and the owners of classes they belong to see it: in the class roster, on the gradebook page, and as an `ra` column in both CSV exports.
- Migration `0049`: drops `finished_onboarding`, replaces the username unique constraint with a `lower(username)` unique index, adds `ra` with a unique constraint, and backfills `ra = username` where the username matches `^\d{7}$` and `ra` is null. The username itself is kept.

## Capabilities

### New Capabilities
- `user-identity`: username format, case preservation and case-insensitive uniqueness; the RA field (format, storage, uniqueness, who can see it); what email signup and social login collect or generate; the migration backfill from RA-shaped usernames; RA in the class roster.

### Modified Capabilities
- `user-onboarding`: whole capability removed (gate, flag and onboarding page no longer exist). The spec directory is deleted at archive, since a spec cannot be left with zero requirements.
- `user-home`: `/home` only requires a session. The "finished onboarding" condition and the onboarding redirect are gone.
- `profile-editing`: the edit form gains an optional RA field. The duplicate-username check ignores case.
- `user-profile-routing`: the username route matches regardless of case.
- `class-gradebook`: students are shown with their RA, and the scores CSV gains an `ra` column.
- `class-results-export`: rows identify the student by name, username and RA. The CSV gains an `ra` column, and RA is added to the allowed-data list.
